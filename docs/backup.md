# Резервное копирование и восстановление

## Автоматика

Контейнер `backup` раз в сутки выполняет `scripts/backup.sh`:

- дамп `pg_dump -F c` в `./backups/daily/`;
- по воскресеньям копия в `./backups/weekly/`;
- проверка целостности через `pg_restore --list`;
- ротация: ежедневные — 7 дней, еженедельные — 4 недели.

Каталог `./backups` находится вне тома БД. Рекомендуется дополнительно
синхронизировать его на внешнее хранилище (rclone/S3) кроном хост-машины.

## Ручной бэкап

```bash
docker compose exec db sh -c 'pg_dump -U $POSTGRES_USER -d $POSTGRES_DB -F c' > manual.dump
```

## Восстановление

```bash
./scripts/restore.sh backups/daily/tarobot-2026-08-06.dump
```

## Перенос на другой сервер

1. Разверните проект на новом сервере (docs/deploy.md), не выполняя seed.
2. Скопируйте свежий дамп: `scp backups/daily/... новый-сервер:/opt/tarobot/backups/`.
3. Выполните восстановление `./scripts/restore.sh <дамп>`.
4. Перенесите `.env` (или заполните заново) и перезапустите: `docker compose up -d`.

Перед сдачей проекта выполняется тестовое восстановление на чистой БД.
